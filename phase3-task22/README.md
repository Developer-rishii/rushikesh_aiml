## What this is
A working, run-and-verify implementation of all three Stage B/C/D deliverables
from the study guide, integrated and attack-tested per Stage E, scored against

## How to run everything (reproduces every number in this repo)
```bash
pip install -r requirements.txt
python3 integration/run_pipeline.py        # data -> train -> eval, writes experiment_log.json
python3 integration/attack_simulation.py   # LIVE attack #1/#2/#3 -- required verification evidence
python3 integration/failure_injection.py   # induced failure -> confirms safe degradation
```
Everything is seeded (seed=42) and fully reproducible.

## Data honesty note (Real-data quality & correctness, 20 pts)
No PlaceMux production logs are available in this environment. `data/generate_data.py`
generates a statistically realistic, reproducible, production-log-shaped dataset
(4,000 candidates incl. 5.7% adversarial resumes, 200 jobs, 8,000 interaction events
incl. scraper traffic) — every metric below is computed on this data, not asserted.
Before go-live, the exact same code should be pointed at real logged data (impressions/
clicks/applications) — the pipeline does not know or care whether the data is
simulated or real, which is by design so this transfers directly.

## Pitfalls (Section 12 of the guide) — explicitly addressed
- Keyword stuffing defence: ✅ hybrid rule+classifier, capped structural features
- Training on unvetted user-supplied data: ✅ poison detector quarantines before retraining
- Offline win never validated online: ✅ `online_effect_proxy_application_capture_rate` in `ranking_eval.json`
- Fairness audit as one-time formality: ✅ computed on every `evaluate.py` run
- No model versioning: ✅ `experiment_log.json.model_versions` (sha256, per run)

## Alternative approaches considered & rejected (Section 8 of the guide)
See `threat_model/threat_model.md` Section 6 for the full reasoning on:
- Rule-based-only stuffing detection (rejected as sole defence — adapts too slowly)
- Hard-blocking flagged candidates (rejected as default — false-positive cost too high
  for real candidates; used only for scraping/extraction clients where it's justified)
