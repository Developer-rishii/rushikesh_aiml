# Model Card — PlaceMux Matching Ranker (Task 22 hardened build)

- **Model**: GradientBoostingRegressor, robust-feature ranker (`ranking_defense/ranker.py`)
- **Model hash**: recorded per-run in `experiment_log.json -> model_versions.ranker_model_hash`
  (Threat T7 — versioning/accountability)
- **Features**: deduplicated skill-overlap count, coverage ratio, capped years-experience,
  stuffing-penalty score. Deliberately excludes raw keyword frequency.
- **Companion model**: LogisticRegression stuffing/adversarial-resume classifier
  (`ranking_defense/stuffing_detector.py`), hash recorded alongside.
- **Training/eval data**: simulated production-shaped logs, seed=42, regenerated by
  `data/generate_data.py` (see README "Data honesty note").
- **Known limitations**:
  - Simulated data cannot capture every real adversarial pattern PlaceMux will see in
    production; thresholds (`QUERY_RATE_THRESHOLD`, `DIVERSITY_ENTROPY_THRESHOLD`,
    repetition-rate cutoff) are starting points and MUST be recalibrated on real logs
    before go-live.
  - Isolation Forest poison detector precision (~0.45 on this data) means real audits
    will review some false positives — by design, flags are quarantined for human
    review, never auto-deleted.
- **Fairness**: `ranking_defense/evaluate.py` reports true-relevance-at-top-k by
  protected group on every run; `fairness_max_group_gap` should be tracked over time,
  not read once.
- **Failure mode**: on model exception/timeout, serving layer falls back to a
  deterministic recency ranker (`integration/failure_injection.py`), never an
  unranked or empty result.
